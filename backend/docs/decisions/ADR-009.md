# ADR-009: Human-in-the-Loop Architecture

## Context
The AI must not autonomously execute high-risk actions (e.g. large refunds) without a human decision, but should be able to auto-approve clearly low-risk ones.

## Decision
AI Service's decision node sets requires_approval based on risk. Workflow Service, not AI Service, owns the WAITING_FOR_APPROVAL state and the Approval record; only after an explicit approve does Workflow Service dispatch the side-effecting action to Integration Service.

## Alternatives Considered
- Always require approval: simpler, but defeats the purpose of automation for the (majority) low-risk cases.
- Let AI Service call Integration Service directly and 'ask forgiveness': rejected -- violates the core AI-safety requirement that the LLM never directly triggers a side-effecting action.

## Consequences
The approval gate is enforced structurally (Integration Service is only ever called by a worker acting on Workflow Service's explicit dispatch, never by AI Service), not just by convention, so a prompt-injected or hallucinating LLM cannot bypass it.
