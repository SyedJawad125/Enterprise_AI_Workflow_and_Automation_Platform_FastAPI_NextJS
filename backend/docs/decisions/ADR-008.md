# ADR-008: Why LangGraph (and where it stops)

## Context
The AI reasoning path (intent -> plan -> tool selection -> tool execution -> validation -> decision) has real branching and state that benefits from an explicit graph, but the rest of the platform's control flow (workflow state transitions) is deterministic and doesn't need an AI framework.

## Decision
Use LangGraph only inside AI Service, for the reasoning sub-graph. Workflow Service's state machine is plain Python/SQLAlchemy (app/orchestrator.py).

## Alternatives Considered
- LangGraph for the whole workflow engine: rejected per spec section 8/54 -- would hide simple deterministic transitions behind an AI-oriented abstraction they don't need, and would tie a core piece of business infrastructure to an AI framework's release cadence.

## Consequences
Two orchestration layers to reason about (LangGraph inside AI Service, hand-rolled state machine in Workflow Service) instead of one -- the trade-off is intentional: each layer uses the tool suited to what it's actually orchestrating.
