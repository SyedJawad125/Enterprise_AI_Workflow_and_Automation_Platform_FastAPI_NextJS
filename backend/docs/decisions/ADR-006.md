# ADR-006: Synchronous vs Asynchronous Communication

## Context
Some calls need an answer to proceed (was the login successful?); others are long-running or can be decoupled from the caller (run the AI reasoning step).

## Decision
Sync (HTTP) for: Gateway-to-Auth, Gateway-to-Workflow (CRUD/reads), AI Service-to-Integration Service (tool calls), workers-to-their-target-service. Async (Celery-over-RabbitMQ) for: Workflow Service dispatching ai_analysis/execute_action/notify steps to workers.

## Alternatives Considered
- All-sync: simpler mentally, but ties the HTTP request thread up for the full duration of an LLM call or an external API call, and provides no natural retry/backoff mechanism.
- All-async (even auth/reads): would force the frontend to poll for a login result -- unnecessary latency and complexity for operations that are inherently request/response.

## Consequences
Callers must decide per-interaction which model fits, which is exactly the distributed-systems judgment call this project is meant to demonstrate.
