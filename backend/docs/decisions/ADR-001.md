# ADR-001: Why FastAPI

## Context
Project 1 and 2 already used FastAPI. Project 3 needs native async support (I/O-bound: many HTTP calls between services, an LLM call, a message broker), automatic OpenAPI generation for 7 services, and Pydantic v2 for both request validation and event-contract schemas.

## Decision
Use FastAPI for every service and worker-adjacent HTTP surface.

## Alternatives Considered
- Flask + extensions: mature, but async support is bolted-on, not native.
- Django REST Framework: batteries-included but heavier than needed for narrow, single-purpose services.

## Consequences
Consistent framework across all 7 services lowers cognitive load; async-native fits an I/O-heavy, event-driven system; auto-generated OpenAPI docs double as the API contract documentation.
